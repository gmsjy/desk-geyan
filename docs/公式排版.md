# 数理公式排版（高中物理 / 数学子集）

给挂件加公式显示这件事，最后落在 `src/tex.rs` 一个文件里 ——
**不引 typst、不引 MathJax、不生成位图**，公式仍然走原来的 GDI 逐字绘制。

## 为什么不用现成引擎

| 方案 | 结论 |
| --- | --- |
| **typst** | 0.13 → 0.15（2026-06）三个大版本都没实现直排。社区对照 W3C《中文排版需求》的文档原话是「typst 目前连基础直排都难以实现」；唯一的第三方竖排包 `vtzone` 自称「功能有限、代码质量可疑」。**挂件的招牌就是竖版卷轴，这条直接否决。** 另外它是十几到几十 MB 的依赖（`typst-world` 自标 ~98MB），而本 exe 现在 717 KiB；它的数学字体也跟用户在设置面板里选的中文字体对不上。 |
| **MathJax / KaTeX** | 要 JS 运行时，等于给一个 700 KB 的 Win32 程序塞一个浏览器。 |
| **公式画成图片** | 与逐字动效、缩字档、跨屏 DPI 全部打架，且失去矢量的清晰度。 |
| **自己写子集** ✅ | 高中阶段的公式结构**可枚举**，砍掉矩阵 / 多行对齐 / 积分上下限之后，剩下的就是「递归量盒子」。几百行 Rust，产出仍是「每个字画在哪」的表 —— 竖排、动效、DPI 全部天然继承。 |

## 支持的语法

结构（`{}` 可省为单字）：

| 写法 | 效果 |
| --- | --- |
| `x^2` / `x_0` / `v_0^2` | 上标 / 下标 / 两者并排 |
| `\frac{a}{b}` | 分式（横线自动居中，分子分母降到 0.82 号） |
| `\sqrt{x}` | 根号（`√` 按被开方内容的**墨迹**缩放，上横线自动伸缩） |
| `\vec{v}` | 矢量箭头（贴在字母墨迹上缘） |
| `\sum_{i=1}^{n}` / `\lim_{x \to 0}` | 大算符，上下限放在**符号上下方** |
| `\left( … \right)` | 自动缩放的定界符（`( ) [ ] { } | < > /`，`\{` `\}` `\|` 走命令写法），比例见下 |
| `\cdots` / `\ldots` | 省略号：中线三点 / 基线三点（画成方点，不用字符） |
| `\sin \cos \tan \log \ln` … | 直立函数名 |
| `\,` `\;` `\quad` `\qquad` | 显式空白 |

希腊字母：`\alpha` … `\omega`、`\Gamma` … `\Omega`。
符号：`\cdot \times \div \pm \mp \le \ge \ne \approx \propto \infty \to`
`\degree \angle \perp \parallel \triangle \therefore \because \in \subset \cup \cap \int \partial \nabla`。

**不做**（写下来防止范围悄悄膨胀）：矩阵 / 行列式、`aligned` 多行对齐、
`\overbrace` / `\underbrace`、积分上下限。

### `\left…\right` 放大到什么程度

没有 OpenType 的可伸缩字形变体，做法和根号一样：**探针 + 等比放大字号**。
100px 探针量出定界符墨迹高，按「内容高度 + 0.06em 边距」反算目标字号，
上限 2.4 倍。所以又高又窄的分式外面那对括号，笔画会比正文粗一点 ——
换来的是任何字体下都能自适应，不必给每个字号手调常数。
`\left.` / `\right.` 是空定界符（这一侧不画、不占宽度）。

## 坐标系（改代码前必读）

`MBox` 里所有 `y` **相对基线、向上为负**；`Item::Glyph.dy` 已经减掉了该字号
的 `ascent`（也就是「单元格顶」的偏移），所以绘制方只需要 `TextOutW(dx, dy)`，
**不必再查任何度量**。换算只发生在 `glyph()` 一处。

## 五个踩过的坑（都是「看着对、画出来错」）

1. **根号不能按 `ascent` 摆。**
   `tmAscent/tmDescent` 是给一整行留位的行度量，单个 `√` 的墨迹只占其中一部分
   且重心偏下。第一版按行高摆，结果整根掉到被开方内容**下面**，还把下一行顶穿。
   现在用 `GetGlyphOutlineW(GGO_METRICS)` 取**真实墨迹框**，先 100px 探针量出
   「墨迹高 / 字号」比值，再按目标高度反算字号 —— 换任何字体都不用改常数。

2. **分式的竖直定位要用字体行度量，不能用子盒的 `ascent`。**
   分母是 `r^2` 时，它的盒子 `ascent` 里含着**抬高的上标**，按它摆会把分母
   推下去一大截：现象是横线紧贴分子、分母掉在半空。

3. **矢量箭头要贴墨迹，不是贴行高。**
   按 `ascent` 摆，拉丁大写字母上方会空出十几像素，箭头看起来像一条飘着的上划线。

4. **`⋯`（U+22EF）在中文字体里普遍没有字形。**
   第一版把 `\cdots` 映射成这个字符，屏幕上出现三个**方框** —— GDI 没有
   「缺字形就换字体」的习惯，它直接把豆腐块画出来。改成三个 `FillRect` 方点
   （`Item::Dots`），一点也不吃字体的饭，横竖版还都一致；中线档对齐 `+` 的
   **墨迹中心**，而不是写死 0.28em。

5. **公式缩字号要按比例一步到位。**
   竖版里公式比版心高时要缩。原来每次 `×0.85` 试，一条高出两倍的公式得排
   五六遍，每遍都是几十次 GDI 量字 —— 实测竖版排版 1278 µs/帧，红线是 1200。
   字形 advance 与字号是线性的，直接按比例算出目标字号、最多再校正两次，
   同样的句子降到 580 µs/帧。

还有个小细节：`-` 在数学里是 U+2212（长减号），不是 ASCII 连字符，解析时会替换。

## 用法

```bash
desk-geyan.exe --math dist/math-demo.png            # 出样张（14 条高中公式 + 读数）
desk-geyan.exe --mathquote "质能关系 $E = mc^2$ 说明质量就是能量"  # 走真实渲染路径，横竖各一张
```

`--math` 逐条打印 `宽 / 总高 / 上高 / 下深 / 图元数`；`--mathquote` 打印字形数、
公式块数、缩字档位、占位、是否截断、公式块位置与盒子，以及**排版耗时**
（200 次均值）。两者在解析失败时都会兜底成普通文字（词库里一条公式写错，
正确表现是「难看但能看」，不是「这一屏什么都不画」），`--math` 另标 `[WARN]`。

## 接入生产的形态（已完成）

- `tex::layout` 摊成 `layout::Atom`，由 `layout_rich` 排成 `Glyph` 表 + `Vec<MathBlock>`；
  公式**不进** `glyphs`（它含横线 / 箭头 / 方点等非字符图元），另走 `draw` / `draw_rot`。
- 横版：公式当「不可拆的宽字」参与贪心折行，基线对齐，含公式的行按墨迹撑高。
- 竖版：公式整块顺时针转 90°（`lfEscapement = 2700`），列宽逐列单独算。
- 跑马灯里公式句**照样滚**：跑马灯原本是整串 `TextOutW`（画 `display()` 原文，
  公式会露出 `$...$`），现在含公式的句子改走定位表 —— 排版一次、按横向偏移画，
  宽度取 `extent`；纯文字句仍走老路，一个字节没改。
  - 竖直裁剪给**整个窗口高**，不是版心：含分式的句子比版心高，按版心裁会把
    分母 / 根号下沿整条切掉（屏幕上像「字只剩上半截」）。
  - 竖直基准取**汉字行**，不取内容外框。分式有深度（`T = 2π√(L/g)` 的分母 `g`
    落在基线下方一截），外框比一行字高出一倍；拿外框居中会把整句汉字顶到窗口
    上半，看起来就是「有的句子没上下居中」。取字行之后，所有句子的汉字落在
    同一条水平线上，公式该伸多高就伸多高。
  - 排版用的版心宽高取一个极大值（不折行、不截行），排完整体平移到原点
    （`layout::content_origin` / `shift_by`）—— 横版排版会把每行在版心里居中，
    滚动要的是「这一句自己从 0 开始」。
- 缩字阶梯、溢出 / 截断语义、合批断批（`Glyph.brk`）都已接上。
- 内置库末尾有一节「公式格言」（14 条），`assets/quotes-math-sample.txt` 另给用户抄。

## 已知限制

- 括号是等比放大的，不是字体的可伸缩变体：超高分式的括号笔画偏粗。
- 不解析 `\text{}`；公式里要写汉字，直接写（`F_合` 可用）。
- 公式里的空格无意义（间距由运算符规则给），需要空白显式写 `\quad`。
